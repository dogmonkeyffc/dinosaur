# 电视与手机 App 架构

Android 手机与 Android TV / Google TV 都使用 Kotlin 和 Media3。登录、播放与发布流程见 [App 文档](../apps/README.md)。

## 模块

| 模块 | 职责 |
| --- | --- |
| `apps/mobile-native/app` | 手机上的触摸导航、媒体库、观看记录、账号与管理页面、横竖屏播放 |
| `apps/tv-native` | 电视配对、遥控器导航与焦点恢复、大屏播放 |
| `apps/android-common` | Android 客户端共用的服务请求、设备会话存储、媒体目录、播放进度、字幕与品牌资源 |
| `ui` | 独立构建的 Web 客户端 |
| `internal` | Go 服务的认证、媒体库、元数据、扫描和播放等领域及适配层 |

两个 Android 客户端共享网络协议和存储逻辑，并各自维护页面、输入和播放控件。目录、海报、播放与观看记录使用同一个 Go 服务。服务端负责权限校验和播放协商，Media3 按协商结果播放原片或兼容流。

## 会话与资源

- Android 使用独立设备会话，并通过系统安全存储保存凭据。Web 使用 Cookie 会话，写操作验证 CSRF。
- 媒体、海报和字幕请求使用当前服务器和账号。客户端验证资源地址，服务端按用户检查媒体库权限。
- 覆盖安装时继续支持读取旧客户端留下的账号和首页显示设置。设备配对和会话撤销沿用现有 API。
- 设备协议见 [API 契约](../api/openapi.yaml)。

## 构建

`scripts/build_apps.sh` 使用同一 Gradle 工程构建手机和电视 APK。两端分别维护版本、签名和发布产物。`build.sh` 负责构建 Web 并嵌入 Go 服务。签名私钥、依赖缓存和安装包保存在发布环境。

验证 Android 变更时，应覆盖已有版本的覆盖安装、账号恢复、受权限保护的资源、播放与续播，以及电视遥控器返回和焦点恢复。
